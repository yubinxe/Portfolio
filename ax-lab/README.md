# ax-lab — 범용 AX 확장 3종 (C-1 · C-2 · C-3)

**개인 구현 · 공개 시연 (가상 벤치마크 검증)**: 모든 데이터는 가상이며, 실제 기업·고객 자료는 쓰지 않았습니다. 외부 AI를 호출하지 않고, 결정론적 TypeScript 코드로 동작합니다. 김유빈 개인 구현이며, 법무법인 경국(Gyunggook)이 도입한 시스템이 아닙니다. 실무 도입 효과나 시간 단축 효과는 측정하지 않았습니다.

| 앱 | 푸는 문제 | 차단 · 검증 장치 | 배포 경로 |
|---|---|---|---|
| C-1 ReconcileGate — 데이터 교차검증 게이트 | 양식이 다른 CSV · 요약 텍스트 · API JSON을 눈으로 대조하는 일 | 결정론적 Schema Adapter로 읽은 뒤 단위 환산(㎡↔평, 원↔만원↔백만원↔억원)과 키 매칭을 하고, 결과를 MATCH · MISMATCH · MISSING · DUP · ANOMALY로 판정합니다. 사유를 반드시 적어야 하는 사람 승인을 거쳐 정제 CSV와 감사기록 JSON을 내보냅니다 | `ax/reconcile-gate/` |
| C-2 Ops Triage & Circuit Breaker — 리스크 차단형 인바운드 트리아지 | AI가 환불 · 계약 · 법적 클레임에 회신을 자동 발송하는 사고 | 의도 · 긴급도 · 위험 등급을 판별합니다. 회신 초안은 정책 조항 ID(예: `POL-REFUND-03`)를 인용합니다. 차단 사유 코드가 하나라도 있으면 자동 발송 단추가 잠기고 `send()`도 거부합니다(HARD BLOCK) | `ax/ops-triage/` |
| C-3 Claim-to-Source Verifier — 의사결정 메모 팩트체커 | AI 요약 보고서의 수치 왜곡과 출처 혼동 | Stage 1에서 초안을 만들고, Stage 2의 독립 검증이 초안 글자만 다시 읽습니다. 수치 · 단위 · 기간 · 날짜 · 고유명사 · 인과 표현을 인용한 원문 줄과 1:1로 대조하고, 미해결 문장이 있으면 내보내기를 잠급니다 | `ax/claim-verifier/` |

## 설계 원칙

- **LLM과 결정론 분리.** 구조화 추출 단계만 어댑터 인터페이스로 분리했습니다(C-1의 `SchemaAdapter` · `LLMSchemaMapper`, C-2의 `DraftAdapter` · `LLMDraftAdapter`, C-3의 `DraftGenerator`). 공개 시연은 결정론적 구현만 연결했습니다. 계산 · 환산 · 대조 · 차단 판정은 어떤 어댑터를 쓰든 순수 함수가 다시 계산합니다.
- **같은 입력이면 같은 결과.** 엔진에는 난수, 현재 시각, 외부 호출이 없습니다. 이 조건은 포트폴리오 테스트 `test/ax-c.test.mjs`가 검사합니다.
- **오탐도 셉니다.** 심은 결함만 세지 않습니다. 정상 환산 · 반올림 · 표기 차이 같은 함정에서 신호를 낸 경우는 오탐으로, 정상 문의를 차단한 경우는 과차단으로 함께 측정합니다.

## 실제 측정값

빌드 시점에 `npm run build`로 기록한 값입니다. 출처는 `ax/eval-report.json`이고, 수치는 가상 벤치마크 데이터 기준입니다.

| 앱 | Vitest | 벤치마크 |
|---|---|---|
| C-1 | 13/13 통과 | 3개 도메인 시나리오에 심은 결함 15건 중 15건 검출 · 오탐 0건 |
| C-2 | 12/12 통과 | 고위험 · 함정 티켓 12건 중 12건 차단(자동 발송 미탐지 0건) · 정상 8건 중 8건 자동 발송 허용(과차단 0건) · 기대 조항 인용 18/18 · 기대 차단 사유 일치 12/12 |
| C-3 | 11/11 통과 | 고의 왜곡 10건 중 10건 탐지 · 오차 지점(토큰) 특정 10건 · 깨끗한 초안 10문장 모두 VERIFIED · 오탐 0건 |

전체 Vitest 결과는 36/36 통과입니다. 이 수치는 이 저장소에 있는 가상 데이터에서 나온 결과이므로, 실제 업무 데이터에서의 검출률이나 차단율을 뜻하지 않습니다.

## 명령

```bash
cd ax-lab
npm install
npm test          # Vitest — 세 앱의 엔진 · 벤치마크
npm run build     # tsc → vitest(json) → vite build(../ax/) → eval-report.json
```

빌드 결과물인 `../ax/`는 커밋합니다. GitHub Pages와 Vercel(`buildCommand ""`)이 이 폴더를 그대로 서빙합니다. 경로가 `base: "./"`라서 `/Portfolio/ax/…`와 `/ax/…` 어디에서도 동작합니다. 수치를 바꿨다면 포트폴리오 `sections.jsx`의 `AX_C`도 함께 고쳐야 하며, `test/ax-c.test.mjs`가 두 값을 대조합니다.
